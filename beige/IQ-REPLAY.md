# Waterfall IQ replay

Read when: changing IQ retention, waterfall time/frequency seeking, Radio listening routing or replay cleanup.

Radio has an optional Waterfall replay checkbox, on by default when no saved preference exists. An explicitly saved Off remains off. The ordinary waterfall display also defaults on. Double-click a waterfall point to replay its time and frequency through the selected built-in Radio receiver. Before replay starts, a single waterfall click reserves the gesture without tuning or seeking, so center tuning cannot erase the historical point before the second click. Deliberate live dragging and active divider, frequency-scale and unlocked bandwidth drags retain priority.

During replay, click or drag across the spectrum or waterfall to change the historical listening frequency while playback continues from its current time. The golden IQ line and top frequency input show that listening frequency. Top digits, mouse wheel and Left/Right keys also tune the replay receiver; Live restores the live frequency display. Double-clicking the waterfall chooses a new time and frequency. Frequency-only changes preserve the cursor, generation, decoder and queued audio, with atomic offset requests applied by the feeder before processing each IQ block. Reject frequencies whose Radio filter would cross the retained spectrum edge. Live RF tuning, persistent free/center mode, plugins and Recorder remain unchanged by replay tuning.

With the pointer over the graph during IQ replay, Up moves one second newer and Down one second older. Hold Shift for ten-second steps or Alt/Option for 0.1-second steps. Held keys repeat. Time steps start from the advancing IQ cursor and preserve frequency; they use the same decoder restart and short transition as double-click seeking. Requests beyond retained history leave playback unchanged and show a boundary notice. Text entry, active controls and open popups take priority over these time shortcuts. Live mode and the separate audio rewind cursor are unaffected.

Retention follows visible waterfall height and the actual FFT sample interval, with eight rows and two seconds of safety margin. This supersedes the initially requested fixed two minutes. Small layout differences keep the current reservation when at least one second of headroom remains. A substantial growth or speed change rebuilds storage; shrinking below 80% of its reservation also rebuilds. Rebuilds invalidate old generations, return listening to live and refill history. At 800 kS/s, 404 rows and 20 FFT frames/second, storage is 22.6 seconds and 144.64 MB, plus a bounded 16 MB write queue.

The stored samples are full displayed-bandwidth complex floats after the frontend's existing decimation/preprocessing, without lossy quantization. A separate Radio listening demodulator consumes historical IQ. Existing live VFOs, plugin IQ/AF hooks, live audio history and Recorder taps remain live. The historical listening path uses the selected built-in mode, bandwidth, demodulator settings, high-pass and deemphasis; external NR/decoder plugins keep processing live data. WFM replay does not launch another RDS decoder or overlay.

Use bounded asynchronous disk writes and preallocated temporary storage. Check capacity plus a free-space reserve before enabling. Allocation, write, read, queue-overrun and disk-space errors disable the feature with a visible message and restore live listening. On macOS the open temporary file is unlinked, so close or process death releases its storage. Join every worker before releasing its inputs or deleting its storage. Debounce layout changes before resizing storage; invalidate incompatible row stamps safely during reconfiguration. Never index a buffer from unchecked floating-point pixel coordinates.

Sample positions, acquisition generation, captured center and sample rate identify history. The FFT framing path used while enabled attaches the actual window's sample position to every existing waterfall row. Sidecar row stamps rotate/resize with the existing raw FFT ring, preserving the mapping used for the displayed pixels. No click conversion based on assumed FPS or waterfall row age. Reproject all history when zooming while enabled, so older pixels and frequency coordinates agree. Retuning hardware, changing source/rate and restarting reception invalidate incompatible history. Reject expired or invalid points rather than clamping them to a different signal.

The waterfall context menu includes Live. The existing audio rewind Live action returns both transports to live, including when audio history is disabled or empty. Other audio-history controls keep their own cursor and do not seek IQ; exports still save live audio history. Double-clicking a valid IQ point returns that Radio's audio transport to its current listening position so the new historical demodulation can be heard. An explicit IQ replay marker shows time and frequency separately from live RF tuning. A short preroll and five-millisecond transitions reduce startup gaps and switching clicks. Short tails at the stopped capture's boundary finish rather than waiting indefinitely for preroll.

`iq_replay_store_test.cpp` exercises exact float preservation, wrapping, expired reads, concurrent reading/writing with generation resets, allocation/read/write/queue failures, reserved disk space and unlinked temporary files. `iq_replay_mapping_test.cpp` exercises randomized source packet boundaries, exact FFT window centers, discontinuities, resize rotation, frozen displayed snapshots, fractional/NaN/outside clicks, retention arithmetic and frequency/generation boundaries. Both run normally and under AddressSanitizer.

`iq_replay_smoke.py` uses a disposable five-module profile containing File Source, Radio, Noise Reduction, Null Audio Sink and Recorder. Its 800 kS/s fixture has two AM carriers and a time-varying tone. It checks actual listening samples, frequency-only retuning with a continuous timeline, rapid retuning, unchanged live RF/tuning flags, invalid/filter-edge rejection, zero underruns away from EOF, independent audio rewind, live Recorder isolation, all eight Radio modes, stale/outside seeks, restart invalidation, a one-sample tail, filesystem failure auto-off/recovery and release on disable. Use `--create-fixture` at a new path beneath the QA folder to generate the fixture. The test-only Null sink offers bounded audio snapshots and optional real-time pacing; ordinary receiver output paths are unchanged.

Never run synthetic IQ against the normal profile. QA endpoints are under `/proc/iq-replay/`: `enabled`, `status`, `seek`, `frequency`, `time-step`, `live` and the last displayed `map`. The `frequency` setter tunes only an active replay without seeking time; `time-step` accepts signed seconds relative to its current cursor. Mutations use the existing UI request queue. Status reports actual sample positions, storage generations, selected point, audio frames and underruns. HTTP stays disabled for normal launches.
